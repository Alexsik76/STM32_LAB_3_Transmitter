## 🔍 Огляд

Цей проєкт є **передавачем** (Transmitter) для системи бездротового керування. Він зчитує дані з органів керування, відображає статус на OLED дисплеї та передає пакети на приймач.

Підтримує три режими роботи (перемикання кнопкою):
1. **Режим джойстика (JOYSTICK)** - зчитування аналогових координат (X, Y) для керування сервоприводами.
2. **Режим клавіатури (KEYPAD)** - сканування матричної клавіатури та відправка символів.
3. **Автоматичний режим (SEQUENCE)** - генерація та відправка тестової послідовності даних.

## 🛠 Апаратна частина

### Основні компоненти
- **MCU**: STM32F103C8T6 (ARM Cortex-M3)
- **Радіомодуль**: NRF24L01+ (SPI + GPIO)
- **Дисплей**: 0.96" OLED SSD1306 (I2C)
- **Ввід**: Аналоговий джойстик, Матрична клавіатура 4x4, Кнопка зміни режиму.

### Схема підключення (Pinout)

| Компонент | Інтерфейс | Піни STM32F103 | Опис |
| :--- | :--- | :--- | :--- |
| **NRF24L01** | SPI1 | PA5 (SCK), PA6 (MISO), PA7 (MOSI) | Шина даних |
| | Control | PB0 (CE), PA4 (CSN) | Управління радіо |
| **OLED SSD1306**| I2C1 | PB6 (SCL), PB7 (SDA) | Графічний інтерфейс |
| **Joystick** | ADC1 | **PA0** (Axis X), **PA1** (Axis Y) | Аналоговий ввід |
| **Keypad** | GPIO | PBx (Rows/Cols) | Матриця кнопок |
| **Mode Button**| GPIO | PAx (External Interrupt/Poll) | Перемикання режимів |

## 🏗 Архітектура програми

Система побудована на базі **FreeRTOS** за шаблоном "Producer-Consumer" (Виробник-Споживач).

### RTOS Tasks (Задачі)
1.  **`InputScanTask` (Producer)**: 
    * Пріоритет: `High`
    * Відповідає за опитування АЦП (джойстик) та GPIO (клавіатура).
    * Формує структуру стану та кладе її в чергу.
2.  **`RadioTxTask` (Consumer)**: 
    * Пріоритет: `Normal`
    * Очікує дані з черги `xQueueInputData`.
    * Керує модулем NRF24L01 для відправки пакетів.
3.  **`DisplayTask`** (опціонально в контексті TX):
    * Оновлює локальний OLED дисплей для відображення поточного режиму та значень.

### Синхронізація
* **Queue (`xQueueInputData`)**: Буфер для безпечної передачі даних між задачами сканування та радіопередачі.
* **Mutex**: Використовується для захисту доступу до шини I2C (дисплей).

## ⚙️ Функціональність

### 1. Режим Джойстика
* **Вхід**: 12-бітні значення АЦП (0...4095).
* **Обробка**: Накладання "мертвої зони" (Deadzone) для стабільності центру.
* **Пакет**: Тип `JOY`, Payload: `{x: uint16, y: uint16}`.

### 2. Режим Клавіатури
* **Вхід**: Натискання клавіш (0-9, A-D, *, #).
* **Обробка**: Усунення брязкоту контактів (Debounce).
* **Пакет**: Тип `KEY`, Payload: `{char: uint8}`.

### 3. Режим Послідовності
* **Логіка**: При натисканні клавіші запускається автоматична відправка наперед визначеного масиву байт або інкремент лічильника.
* **Використання**: Для тестування стабільності каналу зв'язку.

## 🚀 Налаштування

1.  **Живлення NRF24L01**: Обов'язково припаяти конденсатор **10-100uF** між VCC і GND безпосередньо на модулі радіо.
2.  **Адресація**: Переконайтеся, що `RX_ADDRESS` у файлі `nrf24_hal.h` збігається з адресою приймача.
3.  **Канал**: За замовчуванням канал **Channel 10** (2410 MHz). Змініть константу `NRF_CHANNEL`, якщо є завади Wi-Fi.

## 📡 Протокол передачі даних

Структура пакету (32 байти max):

```c
typedef struct {
    uint8_t type;      // Тип пакету (0: PING, 1: JOY, 2: TEXT, 3: SEQ)
    uint8_t length;    // Довжина корисних даних
    uint8_t payload[30]; // Дані (Union для різних типів)
```

## ⚠️ Відомі проблеми та рішення
Проблема: NRF24L01 не ініціалізується (Status 0x00 або 0xFF).

Рішення: Перевірити підключення проводів MISO/MOSI. Перевірити живлення 3.3В.

Проблема: Дисплей мерехтить при передачі.

Рішення: Використання окремого LDO стабілізатора або додавання osDelay між оновленнями екрану.

Проблема: "Input Lag" (затримка) реакції.

Рішення: Зменшити період osDelay у задачі InputScanTask.
